# 전역 스킬·MCP 관리 방안

- 작성일: 2026-10-05
- 상태: MCP 공통 정본과 3개 에이전트 배포 도구 구현·최초 관리 이관 완료.
  스킬 관리 자동화·Hermes·원본 의존성 정리는 후속 단계다.
- 대상: Codex, Claude Code, Antigravity, Hermes `edith`.

전역 스킬과 MCP의 관리 원본을 dotfiles 한곳에 두고 에이전트별 설정은 그 원본에서
배포한다. 스킬은 같은 파일을 심링크로 참조하고, MCP는 설정 형식과 파일 소유권에
따라 생성·병합한다. 시스템·플러그인 기능과 프로젝트 전용 기능은 별도 범위를 유지한다.

## 현재 상태와 목표의 차이

공유 스킬 경로는 이미 dotfiles를 참조한다. 다만 직접 제작 Raindrop 스킬 2개는
`sejong-wiki`, Understand Anything 스킬은 외부 체크아웃을 원본으로 참조한다.
현재 구조와 출처는 공유 스킬 관리 문서와 설치 기록에서 확인한다.

DEVONthink·Raindrop·Zotero는 Codex·Claude·Antigravity에 전역 등록되어 있다.
세 서버는 공통 명세에서 관리하며 기존 정의가 같음을 확인해 관리 상태로 이관했다.
설정 파일은 최초 이관 시 다시 쓰지 않았다. 이후 변경은 명세 수정·계획·적용 순서로
배포한다. Hermes `edith`는 아직 생성하지 않았다.

## 목표 디렉터리 구조

아래 MCP 명세·출처 기록·배포 진입점은 구현된 경로다.

```text
macos/agents/.agents/
├── skills/                  # 기존 공통 스킬 경로
├── .skill-lock.json         # 기존 스킬 출처·설치 기록
└── mcp/
    ├── servers.json         # MCP 공통 명세
    └── sources.json         # 서버 출처·설치 버전·재현 정보

scripts/
└── sync-agents              # MCP 검사·미리보기·배포 진입점
```

`servers.json`은 실행 정의와 적용 대상을, `sources.json`은 설치·업데이트 근거를
소유한다. 생성 설정·배포 상태·백업은 로컬 관리 디렉터리에 둔다. 인증 파일과
계정·대화·세션 상태는 Git 관리 대상에서 분리한다.

## 스킬: 공통 원본과 심링크

| 에이전트 | 배포 방식 |
| :--- | :--- |
| Codex | 기존 `~/.agents/skills` 공통 경로 참조 |
| Claude Code | `~/.claude/skills`에 공통 스킬별 심링크 |
| Antigravity | 기존 공유 스킬 경로 연결 유지 |
| Hermes `edith` | 프로필의 `skills.external_dirs`로 공통 경로 참조 |

Claude는 스킬별 연결을 유지해 에이전트 전용 스킬과 공존시킨다.
같은 이름의 기존 물리 폴더나 다른 원본 링크가 있으면 충돌로 보고하고 자동 교체하지 않는다.
이름 변경·제외 처리도 도구가 관리하던 링크에 한정한다.

직접 제작한 전역 재사용 스킬은 장기적으로 dotfiles를 원본으로 삼는 것을 제안한다.
Raindrop 스킬 2개를 옮길 때는 `sejong-wiki`의 설치 스크립트·문서·테스트·상대 참조를
함께 점검하고, 영향과 이동 범위를 승인받은 뒤 전환한다. 볼트 운영 스킬 6개는
볼트의 프로젝트 기능으로 유지한다.

외부 스킬은 선택한 버전의 파일을 공통 경로에 설치하거나 고정한 외부 체크아웃을
참조한다. 후자는 저장소·커밋·준비 경로가 설치 기록에 있어야 한다.
스킬 내용·보조 파일·참조 파일 전체가 배포 단위이며, `SKILL.md`만 복사하지 않는다.
업데이트 대상은 승인된 설치 목록과 필요한 의존성으로 한정한다.

## MCP: 공통 명세와 형식별 배포

공통 명세에는 서버 ID, 전송 방식, 실행 명령·인자 또는 URL, 인증 참조,
적용 에이전트·프로필, 활성 여부를 둔다. 홈 경로는 명세에서 변수로 표현하고
배포 시 실제 경로로 해석한다. 에이전트가 모든 필드에서 환경 변수를 확장한다고
가정하지 않는다. 토큰 값은 명세에 넣지 않는다.

공통 서버는 DEVONthink·Raindrop·Zotero다. 별도 서버는 적용 대상을 지정할 수 있으며,
앱 전용 서버와 플러그인 제공 서버는 그 원래 관리 주체가 소유한다.

| 에이전트 | 배포 대상 | 처리 방식 |
| :--- | :--- | :--- |
| Codex | `~/.codex/config.toml` | 공통 서버의 TOML 항목만 병합. 기존 dotfiles 연결 유지 |
| Claude Code | `~/.claude.json` | 최상위 `mcpServers`의 관리 항목만 병합 |
| Antigravity | `~/.gemini/config/mcp_config.json` | 관리 MCP 항목만 병합. 기존 링크·추가 서버는 보존 |
| Hermes `edith` | 해당 프로필 설정 | 설치된 Hermes의 형식 확인 후 공통 서버 항목만 병합 |

Codex·Claude·Hermes는 MCP와 다른 설정이 같은 파일에 있으므로 전체 파일을 공통
JSON으로 교체하지 않는다. Antigravity도 앱이 추가한 서버가 생기면 이를 보존하여
생성한다. 생성 결과는 배포본이며 공통 서버 변경은 명세에서 시작한다.
앱이 설정을 갱신하거나 심링크를 실파일로 대체하면 `check`가 차이를 보고한다.

### 외부 MCP 설치와 버전

MCP 설정 배포와 서버 설치·업데이트는 별도 작업이다. 출처 기록에는 외부 저장소나
패키지, 확인한 버전·커밋, 설치 방법, 실행 경로와 로컬 변경 여부를 남긴다.
공통 원본을 dotfiles로 둔다는 이유로 외부 서버 코드를 모두 복제할 필요는 없다.

현재 Zotero는 이미 설치된 바이너리를 사용한다. Cargo 설치 기록과 추정 원본,
당시 커밋·로컬 수정 여부의 확인 한계는 MCP 출처 기록을 따른다.
기존 바이너리·해시·백업을 보존하면서 설치 출처를 먼저 확정하고 재현 방법을 정한다.
DEVONthink·Raindrop도 업데이트를 수행할 때 검증한 버전을 기록한다.
`@latest`를 고정 버전으로 전환하는 작업은 이번 정본 전환에 포함하지 않는다.

## 배포 도구의 동작 계약

[배포 도구](../../scripts/sync-agents)는 Python 3.11 이상과 `uv`를 사용한다.
PEP 723에 고정한 `tomlkit==0.13.3`으로 Codex 주석·비관리 설정을 보존한다.
현재 지원 범위는 stdio MCP와 Codex·Claude·Antigravity다. 스킬 링크 관리와
Hermes 어댑터는 아직 구현하지 않았다.

| 명령 | 동작 | 완료 기준 |
| :--- | :--- | :--- |
| `scripts/sync-agents check` | MCP 설정 링크·관리 키·실행 파일·인증 파일 조건 검사 | 대상별 일치·누락·충돌·미지원·미검증 상태를 출력하고 파일을 변경하지 않음 |
| `scripts/sync-agents plan --output <새 파일>` | MCP 관리 대상의 추가·변경·이관·제거·충돌 표시 | 적용 전 변경 파일·키·링크와 기존 사용자 변경의 보존 여부를 확인 가능 |
| `scripts/sync-agents apply --plan <파일>` | 저장한 계획과 현재 상태를 비교한 후 백업·적용 | 무관한 항목 보존, 실패 시 복구 가능, 반복 적용 시 변경 없음 |

도구는 이전에 관리한 서버 ID와 배포 값을 로컬 상태로 기록한다. 스킬 링크 목록은
아직 관리하지 않는다. 최초 이관은 기존 실행 정의가 명세와 같은 경우에 허용하며,
다른 기존 정의 또는 명세 밖 필드는 충돌로 보고한다. 정본에서 항목이
빠져도 모든 사용자 항목을 지우지 않고 그 관리 범위만 제거 후보로 올린다.
적용 직전 파일이 미리보기 이후 바뀌었으면 중단하고 다시 미리보기한다.
파일은 임시 생성·구문 검증 후 교체하며, 일부 대상만 성공했으면 대상별 결과와
복구 방법을 남긴다. 계정·런타임 파일 백업은 Git 밖의 제한된 권한 경로에 둔다.

### 실행과 복구

```bash
scripts/sync-agents check
scripts/sync-agents plan --output /private/tmp/global-mcp-plan.json
scripts/sync-agents apply --plan /private/tmp/global-mcp-plan.json
scripts/sync-agents check
```

계획 출력 경로는 새 파일이어야 한다. `check`의 종료 코드는 일치 `0`, 차이·전제 조건
누락 `1`, 구문 오류·미지원·손상된 상태·미복구 작업 `2`다. `plan`은 충돌도 계획에
표시하며, `apply`가 충돌을 거부한다. `check`는 서버를 실행하지 않으며 연결 상태는
항상 미검증으로 출력한다. 앱이 설정 심링크를 실파일로 바꾸면 `unlinked`, 다른
원본 링크이면 `different-link`를 출력한다. 자동 재연결은 하지 않는다.

상태·백업은 `~/.local/state/sync-agents/`에 저장하며 디렉터리 `0700`, 파일
`0600`을 사용한다. 일부 실패 시 성공 대상과 복구 정보를 저널에 남기고, 복구 전
새 검사·계획·적용을 차단한다. 다음 명령은 해당 적용 전체를 이전 상태로 복원한다.

```bash
scripts/sync-agents restore --backup ~/.local/state/sync-agents/backups/<적용 ID>
```

복구는 현재 파일·링크·상태가 백업 당시 값 또는 해당 적용 결과와 일치할 때만
허용한다. 이후 사용자 변경이 있으면 자동으로 덮어쓰지 않는다. 복구 중 중단도
재실행 가능하다. Claude 백업에 계정 정보가 포함될 수 있으므로 로컬 비공개 경로를
유지하며 Git에 옮기지 않는다. 설정 부모 디렉터리가 없으면 먼저 준비해야 한다.

임시 홈 통합 테스트와 실제 연결 검사는 분리한다. 연결 검사 스크립트는 볼트 밖
임시 디렉터리에서 세 서버의 `initialize`·`tools/list`만 실행한다.

```bash
uv run --with tomlkit==0.13.3 --with mcp==2.3.0 python -m unittest discover -s scripts/tests -v
uv run --script scripts/tests/verify_mcp_connection.py
```

## 전환 순서와 완료 기준

| 단계 | 변경 범위 | 완료 기준 |
| :--- | :--- | :--- |
| 1. 책임·현황 확정 | 현재 링크·설정·출처·프로젝트 중복 등록 조사 | 정본·배포본·보존 항목과 변경 예정 파일을 검토 가능 |
| 2. 공통 MCP 명세 | 세 서버 실행 정의·출처 기록 작성 | 기존 전역 설정과 의미가 같고 인증 값이 포함되지 않음 |
| 3. 배포 도구 | `check`·`plan`·`apply`와 관리 범위·백업 구현 | 충돌 감지·사용자 항목 보존·반복 적용·부분 실패 복구 검증 |
| 4. 에이전트 연결 | Codex·Claude·Antigravity 반영, `edith` 생성 작업 연계 | 각 에이전트가 공통 스킬을 발견하고 세 MCP에 연결·도구 조회 성공 |
| 5. 원본 의존성 정리 | 직접 제작 스킬 이동 검토·외부 출처 재현, 프로젝트 중복 정리 검토 | 다른 환경에서 준비 가능하고 기존 프로젝트 흐름이 보존됨 |

현재 단계 2의 세 서버 명세와 단계 3의 MCP 배포·복구 도구는 구현했다.
단계 4는 세 에이전트 설정의 관리 이관까지 완료했으며 각 앱의 실제 발견·재로딩과
Hermes는 남아 있다. 전체 스킬 범위를 포함하는 도구 완료로 표시하지 않는다. 스킬 이동과
프로젝트 MCP 제거는 대상·영향을 제시하고 별도 승인 후 실행한다.
Hermes는 `edith`만 대상으로 하며 기존 프로필과 활성 프로필 선택을 유지한다.

검증은 볼트 밖의 작업 디렉터리에서 수행한다. 설정 구문·정본 일치·링크 상태,
에이전트의 실제 스킬 발견, MCP `initialize`·`tools/list`를 나누어 기록한다.
서버 연결과 인증·서비스 기능 검증도 구분하며, 외부 쓰기를 연결 검사에 포함하지 않는다.
샌드박스와 외부 실행 결과가 다르면 실행 환경과 실패 조건을 함께 남긴다.
